# 管理面板合并 + 资金跟随方案（2026-10-14 定稿）

用户拍板：① 资金跟随实时余额（只在低位设下限，不设上限）② 手机友好 ③ 一起做。
本文件是实施依据；实现完成后本文件即成为「设计记录」。

## 1. 资金跟随（影响真钱，先做）

**问题**：原实现的下单基数是配置里写死的 `equity`（100U），全代码没有任何地方把交易所的
实际权益回写。后果：账户涨到 120U 每笔仍只 risk 2U（不复利）；跌到 80U 每笔仍 risk 2U
（相对风险悄悄升到 2.5%）。

**设计**

- 新增配置 `equity_mode`：`follow`（默认）/ `fixed`
- 生效基数 = `floor(实时权益 / 10) * 10`，再取 `max(基数, equity_min)`
  - **实时权益** = 现货 USDC + 浮盈（统一账户口径，`snapshot.equity_total`，已有，无需新增请求）
  - **取整到 10U** 是阻尼：几毛钱的浮亏浮盈不会让仓位跳动
  - **只设下限**（`equity_min`，默认 20U）：用户明确「上限没必要」——充值到 1000U 就按 1000 算
- 用户入金后**自动生效**：下一笔信号即按新权益算，不需要通知 agent、不需要改配置；
  基数变化 >20% 时写一条 `hl_events`（面板可见），便于回溯「什么时候基数变了、为什么」
- 读不到交易所权益时**回落到配置值**（`equity`），并记 WARNING —— 绝不让「读不到」变成「按 0 下单」
- 每日亏损熔断、名义上限闸门用**同一个基数**（口径一致）
- 面板显示：当前生效基数 / 实时权益 / 模式；并列出最近 10 次基数变化

**不采纳**：上限（用户否决）、复杂迟滞状态机（取整已足够，且无状态更好测）。

## 2. 面板合并（纯展示层，不动交易逻辑）

**一个入口**：`/admin?k=<ADMIN_TOKEN>`，四个 Tab，服务端渲染（零 JS、零 CDN，手机弱网可用）。

| Tab | 内容 | 来源 |
|---|---|---|
| 总览 | 状态条（模式/熔断/对账/HL 延迟/更新时间）→ 账户卡 → 仓位表（止损 ✅❌）→ 交易所挂单 → 权益曲线 → 最近执行器事件 | 复用 `hl/views._render_body` |
| 参数 | 策略组 / 执行组 / 资金组，每项显示当前值 + 来源（DB·env·默认）+ **改动影响预览**（按当前价算单笔风险/名义/保证金/强平价） | 由旧 `/admin/rules` 扩容 |
| 开关 | **执行模式三选一**（只通知 / 影子 / 实盘，切实盘二次确认+校验凭据）、推送开关（心跳/日报周报/成交回报）、kill switch | 由旧 `/admin/hl/mode`+`kill` 升级 |
| 记录 | 下单记录 / 成交 / 提醒日志 / 执行器事件 | 由旧 `/admin/logs` 扩容 |

**保留**
- `/c/{pid}` 确认页：**保留**。它是「只通知」模式唯一的记账入口，而「只通知」是要长期保留的回滚开关。
- `/hl` → 301 到 `/admin?tab=overview`：**保留**（这个地址出现在已发出的消息里/可能已存书签）
- `/admin/rules`、`/admin/logs` → 301：保留（同一段重定向代码，删反而更麻烦；若日后要清理，删 3 行即可）
- `/api/hl/*` 四个 JSON 接口：原样保留（看守、巡检脚本在用）

**语义澄清（回答「上线后纯通知就停了」）**
- 切到 `live` 后，执行器接管开仓/离场，**人工操作卡自动不再发送**（无需额外开关）
- 「只通知」= 执行模式 `off`，任何时候切回即回滚；切换时页面明确提示影响
- 心跳/日报/周报推送保持独立开关（它们是这个服务的体检报告，与交易无关）

## 3. 学到的做法（出处）

- freqtrade FreqUI：顶部常显 dry-run/live 徽章；Settings 独立视图；配置改动要显式生效反馈 → 采纳
  （我们改成「保存即写 DB + 回显下一轮生效」，因为本系统本来就是 DB 优先、无需重启）
- freqtrade `stake_amount: unlimited` + wallet 显示：按钱包余额下注 → 正是本次「资金跟随」，
  并采纳「把当前生效基数显示出来」
- FreqUI 的 start/stop 与 force entry/exit → 只采纳起停（模式开关 + kill），不采纳强制下单
- **不采纳** FreqUI Ultimate（Vue/Pinia/ECharts）与 Hummingbot Dashboard（Streamlit）：需要
  node 构建或重依赖、依赖外网 CDN，与「手机弱网可开、出问题 curl 就能看」的取舍冲突

## 4. 验收

1. 资金跟随：单测覆盖 follow/fixed/下限/回落；真机把配置基数改成 100 而账户 100.68 → 生效基数 100；
   人为把 `equity_min` 调到 200 验证下限生效，再改回
2. 面板合并：四个 Tab 全部 200 且含关键区块；旧链接 301；`/api/hl/*` 不变；手机（窄屏）不横向滚动
3. 交易逻辑零变更：`strategy.py` 未动；全量测试绿；切 live 前跑一次真单彩排
